## Four lenses
Ground every claim in a specific automation/run/conversation id. Prefer a few high-signal findings over an exhaustive list. Nothing worth reporting → write "No new findings".

**Errors** — Cluster `error_detail` (normalized) per automation; report failure rate and flag any automation running hotter than its own baseline or peers. Split into: (a) known self-healing noise (e.g. `<urlopen error timed out>`/`Errno 110`) — only flag if volume clearly grew; (b) genuine bugs (tracebacks, `TypeError`-shaped messages, concurrency/lock errors, missing-config errors) — name the automation and quote the message; (c) silent failures — run `status=COMPLETED` but conversation `execution_status` is `error`/`stuck` or has a `ConversationErrorEvent` — a real success/failure blind spot. Skip anything with an unchanged fingerprint from a prior run beyond a one-line "still present" mention.

**Resources** — Roll up cost/tokens per automation for the window; flag any automation or single run far outside its own or peers' norm (runaway loop, unbounded context, checkout bloat). Check `du -sh` on `dev_conversations/` and `workspaces/automation-runs/` (never pruned) for disproportionate growth. Flag `timeout` values mismatched with actual run durations.

**Security** — Scan `error_detail`/events for credential-shaped strings indicating a leak or misconfiguration, not an intentional mask — report where and why, never the string. Flag automations (especially externally-triggered ones like `issues.opened`/Slack `app_mention`) whose granted capability exceeds their task. Flag disabled-but-not-deleted or test-named automations still holding live credentials. If `ps -eo cmd` shows secrets as plaintext args to `main.py` (read-only check, don't signal anything), note it once as a standing exposure.

**Skills** — Tabulate `activated_knowledge_skills`/`invoked_skills` frequency; flag over-broad/frequent activation (context bloat) and tasks that plausibly needed a skill that never activated. Note any oversized skill content relative to task need (ties to Resources).
